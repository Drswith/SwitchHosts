# 原生版与 5.0.2 的行为对照

基线：5.0.2 的 9 个 e2e spec（`git ls-tree -r --name-only v5.0.2 -- e2e`）。每项标注原生版的状态，并写明缺口。
状态：✅ 已实现，并有测试或实际运行验证；🟡 已实现但有待确认的部分；⬜ 未实现。

| 5.0.2 spec | 覆盖的行为 | 原生版状态 | 说明 |
|---|---|---|---|
| `local-hosts.spec.ts` | 新建本地条目、编辑内容、保存 | ✅ | 新建、重命名、编辑、保存、`⌘/` 注释切换、未保存提示、行号栏（真实窗口中核对）已完成 |
| `hosts-entry-management.spec.ts` | 增删改、移动、排序 | ✅ | 新建、重命名、移入回收站、上移/下移、「移动到文件夹」、拖拽（前 / 后 / 进入文件夹）均已完成，拖拽在真实窗口中核对过三种情况 |
| `folder-choice-mode.spec.ts` | 文件夹的单选/多选模式 | ✅ | 文件夹面板设置默认 / 单选 / 多选；偏好中的全局选择模式；开关规则在内核（有测试） |
| `system-hosts.spec.ts` | 系统 hosts 只读视图、历史 | ✅ | 只读视图；历史的查看、删除、清空、记录开关、上限与裁剪确认（有内核测试，并截图核对） |
| `trashcan.spec.ts` | 移入、恢复、永久删除、清空 | ✅ | 内核测试覆盖全部操作；界面为回收站面板 |
| `data-transfer.spec.ts` | 导出、导入预览、失败重试、URL 导入 | ✅ | 导出、文件导入预览、URL 导入（本机 HTTP 服务验证成功与 404 失败路径）、失败后的「重试」按钮 |
| `remote-hosts.spec.ts` | 远程条目的创建、编辑、刷新、域名解析、代理 | ✅ | 创建、编辑、刷新、域名列表、DoH 解析模板（内核测试）；代理经内核测试验证 HTTP 与 SOCKS5 两种协议的路由。真实 DoH 查询需要网络，未在本机验证 |
| `preferences.spec.ts` | 偏好的读写、副作用 | ✅ | 四个标签页与 5.0.2 相同：通用、命令、代理、高级。命令与运行历史、DNS、启动行为、数据目录（真实窗口中更改与重置已核对）、语言、系统窗口框架、托盘快捷小窗、使用数据均已实现。下方「有意不同」列出的设置是原生版的等价实现或不适用 |
| `titlebar.spec.ts` | 自绘标题栏 | ✅（不适用） | 原生版使用系统标题栏，该 spec 对应的功能不再需要 |

## 有意不同（5.0.2 中的设置，原生版的等价做法或不适用）

| 5.0.2 设置 | 原因 |
|---|---|
| 语言 | 提供「跟随系统」「简体中文」「English」三项，只包含中文与英文（决定）。切换后需要重新启动（`AppleLanguages`） |
| 使用系统窗口边框 | 默认关闭时隐藏标题文字、内容延伸到标题栏下方（与 5.0.2 默认外观相近），开启时使用标准标题栏。切换即时生效 |
| 轻量模式 | 原生版不提供。它是 Tauri 版为减少 WebView 内存消耗而设计的，原生版没有 WebView，不需要释放窗口内容。内核中的 `lightweight_mode` 配置键保留，Tauri 版继续使用 |
| 托盘图标快捷小窗 | 开启时菜单栏项打开开关面板；关闭时打开紧凑列表（同一个 `MenuBarExtra`，窗口样式）。原生版没有 5.0.2 的系统托盘菜单 |
| 发送匿名使用数据 | 开关与 5.0.2 相同，只保存配置值。5.0.2 的代码中该设置没有任何发送行为，原生版也不发送任何数据 |
| 面板的显示与宽度（左右面板） | 侧边栏的显示状态与右侧「信息」面板的显示状态会保存；宽度只作为初始值（`NavigationSplitView` 不提供持久化用户拖动后的宽度） |
| 查找结果的列宽 | 原生版的查找结果是列表而不是表格，没有列宽可以保存 |

## 已用真实运行验证的部分

- 隔离 `HOME` 下启动签名的 `.app`：中文菜单栏、树结构、开关显示正确（截图）。
- 文件夹面板、系统 hosts 历史、查找替换的历史与「显示」定位、`⌘/` 注释切换、从本机 HTTP 服务导入备份、偏好的选择模式（截图）。
- 拖拽：子项重排、条目拖到顶层与文件夹之间均成功写入 `manifest.json`；个别顶层条目的拖拽未能用脚本复现（见上表）。
- 内核与 FFI 的端到端测试：远程刷新（`file://`）、代理（HTTP 与 SOCKS5）、HTTP API（真实 TCP）、导入导出、数据目录的校验（不写入真实的数据目录指针）。
- 原生开关在写入模式未设置时被内核拒绝，系统 hosts 未被改动。

## 未覆盖（需要真实环境或权限）

- XCUITest 工程已建立（`macos/UITests`），但运行需要你开启 Automation Mode（系统安全设置）。

- 应用到系统 hosts 的完整路径（需要管理员授权，测试中刻意未执行）。
- 数据目录的「更改」与「重置」会重新启动应用，只做了内核层的校验测试，没有在本机实际切换过。
- 签名、公证、Sparkle 或其它自动更新（需要 Developer ID 证书与更新源）。
- 托盘快捷小窗关闭时的紧凑列表：代码已编译，离屏渲染中可见结构但文字不显示，菜单栏状态项在本机被挤到溢出区，无法在真实窗口中核对。
- XCUITest：未运行（Automation Mode 关闭，需要本机管理员认证）。
